# ZAMAKAN Marketer

Marketing and creative skills for ZAMAKAN, an **Omani** agency with many clients across Oman and the GCC, working in Arabic and English.
Home market defaults live in `.claude/skills/zamakan-core/agency.json` (OM): they shape production notes and fit, **never limit
output** (default scope global, counts are floors not caps, no regional quotas).
They are built as **sub-skills that share file contracts**, with scripts doing the mechanical work so agents spend tokens on judgement.

**Read `PLAN.md` first.** It has the architecture, every decision made with the user, status per step, and the progress log.

## Where things are
- `.claude-plugin/marketplace.json` + `plugins/zamakan/`: the installable plugin (`/plugin marketplace add SaoudAlawi/ZAMAKAN-marketer`).
  `plugins/zamakan/skills` links to `.claude/skills` (keep the skills as real folders there; bump `plugin.json` version to ship).
  Scripts write to the user's project via `zamakan-core/scripts/workspace.py`, never next to themselves.
- `.claude/skills/zamakan-core/`: shared conventions (client folders, contracts, quality bar) and `scripts/client.py`
- `.claude/skills/zamakan-design-system/`: feature 1, brand files → design system. **Paused after iteration 1**; see PLAN §3 and §5b to resume.
- `.claude/skills/zamakan-reference-scout/`: feature 2, campaign references + analysis. **Active.**
- `.claude/skills/zamakan-shot-scout/`: feature 3, cinematic references (subject, effect, frame-match, who, inspire me) → shot board / viewing programme. **Built v0.2.0.**
- `.claude/skills/zamakan-script-desk/`: feature 4, helps screenwriters (templates, Arabic RTL formatter, ten-viewpoint reader, side comments, charts, draft comparison, intent sheet, margin replies, scene cards, arcs, PDF/FDX input, focused passes, verdict anchors, story idea → template; documentaries: proposal, transcripts → paper edit, A/V script, doc reader, archive log, shoot list). **Built v0.6.0.**
  Never writes the script for the writer. Test script: `samples/script-desk/` (documentary samples in `samples/script-desk/doc/`); its answer key is in `evals/fixtures/script-desk/`.
- `samples/rawaq/input/`: fictional test client (brand PDF, logos, fonts). All development runs on it.
- `evals/fixtures/`: answer keys, gold outputs, and the scout test brief. **Never show these to an agent under test.**
- `library/`: shared, client-neutral reference library (README index + `campaigns/*/REFERENCE.md`), generated by `library.py`.
- `tests/`: pytest suite, which must stay green.
- `clients/` and `*-workspace/` are git-ignored, because real client material stays local.

## Setup & checks
```bash
pip install -r requirements.txt uharfbuzz   # uharfbuzz only for tools/sample-builders (requirements.txt → plugins/zamakan/)
python3 .claude/skills/zamakan-core/scripts/doctor.py   # checks packages, Chromium, LibreOffice, web access
python3 -m pytest -q tests                  # all pass; DESIGN.md linter test skips unless ZAMAKAN_DESIGNMD is set,
                                            # live scout tests skip when offline
curl -sS -o /dev/null -w '%{http_code}\n' https://www.example.org/   # 200 = web access works (Ads of the World itself 403s plain curl; the scripts handle it)
```
Rendering uses Playwright with the preinstalled Chromium (`/opt/pw-browsers/chromium`). The scripts find it automatically.

## Working style the user wants
- Plan together, then **test every step** before moving on. Report results honestly, including weak spots.
- Look for existing work first (MIT/Apache skills, standards) and reuse it rather than rebuilding.
- Commit and push each finished step to the working branch; keep `PLAN.md` status and the progress log current.
- Explain in plain language; the user is an agency person, not necessarily a developer.
