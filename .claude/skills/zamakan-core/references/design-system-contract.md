# Design-System Contract (v1.0)

How every ZAMAKAN sub-skill reads a client's visual identity. Produced by
`zamakan-design-system`; consumed by every sub-skill that makes visual or on-brand output.

## Location
```
clients/<slug>/design-system/
├── spec.json        # SOURCE OF TRUTH: every value + provenance (schema: zamakan-design-system/schemas/spec.schema.json)
├── brand.md         # agent-facing visual guide: read this first
├── tokens.json      # generated: W3C Design Tokens, DTCG 2025.10 (colours as {colorSpace, components, hex})
├── tokens.css       # generated: CSS custom properties + @font-face
├── manifest.json    # generated: every asset (logos, fonts) with usage metadata
├── sources.md       # generated: provenance table, conflicts, open questions, contrast matrix
├── DESIGN.md        # generated: Google DESIGN.md export for DESIGN.md-aware tools (Arabic styles prefixed `ar-`)
├── preview.html/png # generated: visual style tile
└── assets/          # copied, normalised logos + fonts
```
Each token carries `$extensions.zamakan.status` (and `confidence`). Compound CSS values that
DTCG cannot express (e.g. top-only radii, rgba shadows) are also given as `$extensions.zamakan.css`.

Only `spec.json` and `brand.md` are written by the agent. Everything else is regenerated by
`build_design_system.py`, so **never hand-edit generated files**. Edit `spec.json` and rebuild.

## How to consume (cheapest first)
1. **Read `brand.md`.** Its top "Quick reference" block answers most questions in under 60 lines.
2. **For exact values, read `tokens.json`** or reference CSS variables from `tokens.css`.
   Never retype hex values from memory.
3. **For a logo file, look it up in `manifest.json`** by `kind`, `colorway` and `approved_backgrounds`.
   Always pick an approved variant for the background you are placing it on.
4. **Read `spec.json` only** when you need provenance or a rule that isn't in `brand.md`.

## Status of values
Every value carries a `status`:
- `extracted`: stated in the client's files (with file + page). Treat it as law.
- `derived`: computed from extracted values (e.g. a reversed symbol's rules). Reliable.
- `proposed`: the client's files are silent; the agent proposed it, with a rationale.
  Use it, but don't present it to the client as their rule. Flag it if it drives a key decision.

Open conflicts, open questions and **missing assets** are listed in `sources.md`. If your output depends on one
(e.g. a disputed colour), mention it in your delivery notes.

## Token naming (stable API)
| Token path | CSS variable | Meaning |
|---|---|---|
| `color.<id>` | `--color-<id>` | Raw palette colour (e.g. `color.date-brown`) |
| `color.<id>-<pct>` | `--color-<id>-<pct>` | Tint step, if defined |
| `role.<role>` | `--role-<role>` | Semantic alias. Canonical names: `text-primary`, `text-heading`, `text-secondary`, `text-inverse`, `text-link`, `background`, `background-inverse`, `surface`, `surface-alt`, `brand`, `brand-secondary`, `accent`, `accent-secondary`, `divider`, `border`, `success`, `warning`, `error`; client-specific extras start with `x-` |
| `component.<id>.*` | `.z-<id>` class | Component styles (e.g. `button-primary`), referencing colour/radius/type tokens |
| `font.<id>` | `--font-<id>` | Font family stack incl. fallbacks |
| `type.<script>.<level>` | `--type-<script>-<level>-{size,line,weight,family}` | Typography style; script ∈ `latin`, `arabic` |
| `space.<n>` | `--space-<n>` | Spacing scale step (index, from 1) |
| — | `.z-<script>-<level>` | Ready-made CSS class per type style (Arabic classes set `direction: rtl`) |
| `radius.<id>` | `--radius-<id>` | Corner radius |
| `shadow.<id>` | `--shadow-<id>` | Box shadow |

**Prefer role tokens over raw colours.** `role.text-primary` survives a palette update; `color.charcoal` may not.

## Bilingual rules every consumer must apply
- Use `type.arabic.*` for Arabic text and `type.latin.*` for Latin text. Never style Arabic with a Latin token.
- Arabic: `dir="rtl"`, right-aligned, **no letter-spacing**.
- Follow `brand.md` for which language leads in bilingual layouts.
